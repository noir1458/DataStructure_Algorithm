

1. 자료구조의 이해

컴퓨터는 자료를 효과적으로 표현하고 효율적으로 저장 및 처리할 수 있도록 논리적인 구조로 설계하고 분석하여 프로그램에 사용한다.

컴퓨터가 자료를 효율적으로 처리하려면 문제 도출과 변환 단계에서 문제를 자료구조 측면에서 분석하고 구성해야 한다.

2. 알고리즘 성능분석
2-1. 공간복잡도

알고리즘을 프로그램으로 실행하여 완료하는 데까지 필요한 총 저장공간을 의미

필요한 고정공간 + 가변공간



2-2. 시간복잡도

알고리즘을 프로그램으로 실행하여 완료하는 데까지 소요되는 시간.

컴파일 시간(프로그램 특성과 무관, 고정된 같은 시간으로 가정) + 실행시간(컴퓨터의 실행 빈도수에 따라 달라짐, 명령문의 실행 빈도수 계산)

시간 복잡도는 각 알고리즘을 서로 비교하기 위한 것으로, 정확한 실행 시간을 측정하기보다는 실행 빈도수를 구하여 사용한다.

지정문, 조건문, 반복문 안에 있는 제어문과 return문은 시간 차이가 거의 없으므로 하나의 단위 시간을 갖는 기본 명령문으로 취급하여 실행 빈도수를 계산한다. 이 과정에서 입력크기 n에 대한 실행 빈도 함수를 구할 수가 있다.

ex1-1) 피보나치 수열

n<0, n=0,n=1 경우 for문이 실행되지 않기에 실행 빈도수는 의미가 없다.

n>1경우 for문이 n에 따라 반복하여 수행된다. 총 빈도수는 4n+2



3. 알고리즘 성능 분석 표기법
일반적으로 알고리즘의 주요 성능 차이는 실행시간 차이에서 발생한다. 알고리즘을 비교하기 위한 성능 분석 표기는 시간복잡도 표기를 의미한다. 시간복잡도는 실행 빈도 함수에서 입력크기 n에 대한 실행시간의 증가율만 분석하는 Asymptotic analysis이므로, 실행 빈도 함수의 상수항과 계수는 무시하고 n의 증가에 따라 증가율이 가장 큰 하나의 항에 대해서 차수 표기법으로 시간복잡도를 표기한다.



3.1. 빅-오 표기법

함수 f(n)과 g(n)이 주어졌을 때, 모든 n>=n_0에 대해 abs(f(n)) <= c * abs(g(n)) 을 만족하는 상수 c와 n_0이 존재하면, f(n) = O(g(n))이다.

함수의 상한을 나타내기 위한 표기법, 최악의 경우에도 g(n)의 수행 시간 안에는 알고리즘 수행이 완료된다는 것을 보장한다. 먼저 실행시간 함수를 찾고, 함수값에 가장 큰 영향을 주는 n에 대한 항을 한개 선택하여 계수는 생략하고 O의 오른쪽 괄호 안에 표시한다.



3-2. 빅-오메가 표기법

함수 f(n)과 g(n)이 주어졌을 때, 모든 n>=n_0에 대해 abs(f(n)) >= c * abs(g(n)) 을 만족하는 상수 c와 n_0이 존재하면, f(n) = Ω(g(n))이다.

함수의 하한을 나타내기 위한 표기법이다. 어떤 알고리즘의 시간 복잡도가 Ω(g(n))으로 분석되었다면, 이 알고리즘 수행에는 적어도 g(n) 의 수행시간이 필요함을 의미한다



3-3. 빅-세타 표기법

함수 f(n)과 g(n)이 주어졌을 때, 모든 n>=n_0에 대해 c_1 * abs(g(n)) <= abs(f(n)) <= c_2 * abs(g(n)) 을 만족하는 상수 c_1, c_2와 n_0이 존재하면, f(n) = θ(g(n))이다.

빅-세타 표기법은 상한과 하한이 같은 정확한 차수를 표현하기 위한 표기법이다. f(n) = θ(g(n))이 되려면, f(n) = O(g(n)) 이면서 f(n) = Ω(g(n))이어야 한다.

일반적으로 최악의 경우를 고려한 해결책을 찾기 위해서 빅-오 표기법을 주로 사용한다.
